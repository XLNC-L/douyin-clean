一个针对**网页版抖音**（`www.douyin.com`）的 Chrome 扩展：**自动最高清晰度**、**带货广告自动跳过**、**失焦暂停**、**纯净布局**、**视频底部进度细线**，所有功能都能在扩展面板里分项开关。不做列表轮询、不全站监听、不删 DOM 节点 —— 刷视频不卡。

## 最新变化（v1.9.15）

- **左侧导航 / 顶栏精简改为全站生效**：以前这两条 CSS 规则挂在 `html.dyc-feed` 下、JS 也只在刷视频页面调用，所以一进「我的 / 收藏 / 搜索 / 详情页」侧栏又整条冒出来、顶栏图标也回来了。现在导航（`dyc-nav-hidden` / `data-dyc-nav-hide`）与顶栏（`data-dyc-hide`）不再限定页面，路由切换时也会重新应用；
- **顶栏图标组定位更可靠**：以前靠"右上角圆形头像"反推图标组，未登录 / 头像还没渲染时直接放弃。现在优先用顶栏的「通知 / 消息」语义标记定位，真机在个人主页验证可正常隐藏「充钻石 / 客户端 / 壁纸 / 投稿」等。

## 最新变化（v1.9.14）

- **镜像取错了元素（进度不跟 seek 的真凶）**：真机 dump 出播放器结构——`xgplayer-progress-inner` 是**容器**（宽度恒等于父级 100%），真实进度在 `.xgplayer-progress-played` 的 `style.width` 上（例如 `2.1%`）。旧选择器把 `progress-inner` 也算了进去，`querySelector` 按文档序先取到容器，镜像值永远 100%，`duration` 又是 `Infinity`，于是线条彻底不跟；
- 现在只认 `progress-played` / `progress-current`，并且**先读 `style.width` 百分比**再读 `scaleX`；真机模拟 `duration=Infinity` 验证：seek 到 60s 线条 24.6%、180s 线条 73.2%，与原生进度一致；
- **位置改回贴播放器底部**（上一版按视频底边对齐会悬在控制条上方，视觉上像飘起来了）。

## 最新变化（v1.9.13）

这版是真机（`www.douyin.com/video/...` 详情页）实测后修的，四个问题都复现并验证过：

- **快进快退不同步**：真机复现——seek 的瞬间 `video.duration` 会短暂变成 `NaN`，旧逻辑退回 `seekable` 估算总时长，把"已缓冲到哪"当成总时长，143s/286s 的 50% 被画成 67%、57s 被画成 91%。现在会沿用上一次读到的有效时长；
- **暂停后被自动恢复播放**：`quality.js` 等清晰度爬升时有句"换流期间可能自动暂停，顺手恢复"，用的是进入循环前的 `wasPlaying`，用户中途暂停也会被 `play()` 回来。改成只在 `seeking` / 未缓冲好时才恢复；
- **暂停后莫名跳下一条**：暂停时不判定、不跳转（暂停层常带商品 / 推荐文案，容易被误判成带货）；
- **线条掉到画面外**：真机播放器根是 `basePlayerContainer`（不是 `.xgplayer`），容器比 `<video>` 高 48px（控制条区域），`bottom:0` 会让线条落到画面下方。现在按 `<video>` 实际矩形对齐 left / width / bottom。

## 最新变化（v1.9.12）

- **进度线在「时长未知」的视频上改为镜像抖音自己的进度条**：MSE 流的 `duration` 常是 `Infinity`，之前靠 `seekable` / 时间文案估算，个别视频会算错；现在时长不可用时直接读播放器自己那条进度条的 `scaleX` / 宽度，线条与画面里的进度始终一致；
- **新增实时诊断面板**：页面上按 `Alt + Shift + P` 弹出，实时显示「线条挂在哪条视频上 / 应该挂哪条 / 填充值 / 原生进度 / 循环状态」；控制台 `__DYC.progress.log()` 可看最近 40 条 seek / play / ended 事件；
- 进度线每 120ms 复核一次目标视频，换片、播放器重渲染后都会立刻改挂。

## 最新变化（v1.9.11）

- **聊天页视频不再和背景推荐流一起响**：私信抽屉 / 聊天页 / 好友分享弹层里的视频起播时，暂停信息流里正在播的视频，并由 2 秒看门狗复核；这类播放器同时被排除在过滤 / 清晰度 / 浮层 / 进度条之外，不会再「点开好友视频，背后的推荐视频反而滑到下一条」；
- **进度条逐帧循环驱动**：不再用 `requestVideoFrameCallback`（拖动 / 跳转 / 切清晰度时可能长时间不回调，线条会退化成"只会匀速走"），改为 `requestAnimationFrame` 每帧读 `currentTime`，倍速、快进快退、点击跳转都能立刻反映；循环不按事件开关，暂停时拖动也跟得上；
- **播完从头更稳**：`ended` 之后补三次兜底重画，`currentTime` 变小时强制重画；时长兜底值加合理性校验，避免把"当前时间"当总时长导致线条卡在 100%；
- **游戏卡片漏隐藏**：文案随版本变（「评分高达9.3」/「免下载立即玩」），按「以『游戏』开头 或 带游戏推广话术」识别；
- **「1.2万人推荐」跟着浮层一起隐藏**：推荐类浮层统一按「文本以『推荐』结尾 + 小尺寸 + 靠近画面」识别，晚渲染也会补标；
- **直播 / 带货判定分级**：直播的硬信号（直播间链接、`LivePlayer_`、直播时间标签、「直播中」徽标）单独命中即跳过，软信号（单独的「直播」字样、「1.2万观看」）要两条同时成立；带货的强信号（广告徽标、购物卡片、商品卡容器、店铺账号）单独命中即跳过，弱信号（价格 / 购买按钮 / 营销话术）要凑够两条，减少误跳。

## 最新变化（v1.9.5）

- **修复暂停后鼠标唤不醒浮层**：鼠标判定优先用当前活动卡片；视频元素被暂停层隐藏（矩形为 0）时退回卡片矩形，移动/滚动鼠标都能重新显示；

## 最新变化（v1.9.4）

- 游戏卡片在播放器内部也能识别，不依赖哈希类名。

## 最新变化（v1.9.3）

## 它解决什么问题

网页版抖音默认把体验做得很"满"：清晰度默认「智能」不会自己升到 4K、推荐流里混着带货视频、左侧导航和顶栏图标占地方、切到后台还在响。

这个扩展把这些一次性处理掉，并且**只在你刷视频时工作**，其他页面完全静默。

## 安装

### 方式一：下载 Release（推荐）

1. 打开 [Releases](https://github.com/XLNC-L/douyin-clean/releases/latest)，下载最新的 `douyin-clean-v*.zip`；
2. 解压到一个**固定目录**（之后不要删，Chrome 会一直从这里加载）；
3. 打开 `chrome://extensions`，右上角开启「开发者模式」；
4. 点「加载已解压的扩展程序」，选择解压后含 `manifest.json` 的那一层目录；
5. 打开 `https://www.douyin.com/` 即可生效。

升级：下载新 Release 覆盖原目录 → 扩展管理页点「刷新」→ 刷新抖音页面。

### 方式二：克隆仓库

```bash
git clone https://github.com/XLNC-L/douyin-clean.git
```

用「加载已解压的扩展程序」直接选择仓库目录。

## 设置

点工具栏的扩展图标打开设置面板。设置保存在 `chrome.storage.sync`，登录同一 Chrome 账号的设备会同步。

![设置面板示意：功能分项开关与左侧导航逐项保留](docs/settings.svg)

- **功能**：自动最高清晰度、广告 / 带货过滤、直播过滤、失焦自动暂停，各自独立开关；
- **播放进度条**：视频底部进度细线的开关、颜色（取色器 + 6 个预设色），改动即时生效；
- **布局精简 · 左侧导航**：
  - **整条隐藏**（默认，和旧版行为一致）；
  - **自定义保留**：面板会读取当前抖音页面的导航项（精选、推荐、AI抖音、关注、朋友、我的、直播、放映厅、短剧、小游戏），勾选要保留的入口，其余隐藏；侧栏里的「下载 APP」推广、备案 / 协议页脚也会一并隐藏；
  - **仅保留「我的」**：一键预设；
  - **保持原样**：不做任何处理；
  - 「AI 抖音」入口在以上三种模式下都强制隐藏，也不在保留候选项中；
- **布局精简 · 其他**：顶栏图标精简、浮层自动隐藏分别开关；
- 改动即时生效；如果刚更新扩展、内容脚本还没注入，刷新一次抖音页面即可。

> 自定义保留依赖抖音导航的 `tab-*` 语义类名（2026-10 实测仍在用）。如果抖音改版导致一个保留项都识别不到，扩展会放弃逐项隐藏，不会把整条导航清空。

## 为什么不会卡

刷抖音卡顿通常不是抖音本身，而是插件：全站 `MutationObserver(subtree)`、`setInterval` 轮询 `querySelectorAll`、运行时反复改样式触发重排。

本扩展的硬约束：

- **视觉改动全部写在静态 CSS**（[css/content.css](css/content.css)）；运行时唯一的样式写入是底部进度条的 `transform: scaleX()` 与一次性的颜色变量，前者走合成层、不触发重排；浮层标记与看门狗只读取少量几何信息；
- **换视频靠媒体事件驱动**（`loadedmetadata` / `playing` / `emptied`），另有一个 2 秒一次、只比对 `<video>` 引用与**卡片文案指纹**的轻量看门狗兜底，不做列表选择器轮询；
- **进度条由 `requestVideoFrameCallback` 逐帧驱动**（浏览器不支持时退回 `timeupdate`），不是 `setInterval` 轮询；暂停 / 页面隐藏时自然停止；
- **逐项隐藏左侧导航只在 custom / off 模式启用**，观察范围限定在 `#douyin-navigation` 内部（off 模式只用于维持「AI 抖音」强制隐藏），不观察整页；
- **不删 DOM 节点**：过滤只负责切到下一条，绝不动列表结构，虚拟列表与滚动吸附逻辑不受影响；
- **等待时用事件或有限次 `await sleep`**；扫描只在启动 / 换片时做，而且有数量上限。

## 调试

日常使用不需要调试：点工具栏图标就能分项开关。排查问题时在抖音页面按 **`Alt + Shift + D`**（`Ctrl + Shift + D` 被 Chrome 的「收藏所有标签页」占用，按键到不了页面）：

- 控制台打印当前状态：版本、播放器尺寸、清晰度档位、实测分辨率、广告判定、被隐藏的顶栏项；
- 给被隐藏 / 被标记的浮层加 2.5 秒青色描边，方便确认定位是否正确。

日志前缀为 `quality:`、`filter:` 与 `nav:`，例如：

```
[抖音净播] quality: 档位节点 6 个
[抖音净播] quality: 当前=智能 实测=1920p 最高档=超清 4K
[抖音净播] quality: 点档位 超清 4K
[抖音净播] quality: 实测已到 4K(3840)，本条视频不再调整
[抖音净播] filter: 识别到 购物卡片，跳过该视频
```

## 已知限制

- 只适配 `www.douyin.com` 桌面网页版，不支持手机网页版与抖音客户端；
- 抖音前端类名是哈希动态生成的，扩展只依赖 **ID / `data-e2e` / 几何特征 / 语义文本** 定位元素，大改版后可能需要跟进；
- 左侧导航的逐项保留依赖 `tab-*` 语义类名；导航项一个都认不出时会退回「不隐藏」，不会误伤；
- 清晰度受视频源限制：源本身没有 4K 时，抖音会把 4K 顺延到可用最高档，扩展接受这个结果，不会反复重试；
- 网页端播放器把同一条视频的多个清晰度当作「同一条视频」复用同一个 `<video>` 元素，因此扩展用「代次 + 文案指纹 + 卡片 / 封面旁证」而不是 `duration` / `src` 来判断换片；
- 进度线优先用 `video.duration`；MSE 点播读不到有限时长时会退到 `seekable` 或播放器总时长文案；直播等确实没有总时长的场景不显示进度线。
